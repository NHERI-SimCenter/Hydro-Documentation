5. Capabilities

Version 4.2.0 of the HydroUQ app was released on August 20th, 2025. The following lists the functionality available in this current version. (Note: New features and fixes in this release are marked blue in the following list of features.)

  1. Water Event Selection: Users are provided with multiple paths for water borne hazard generation:

    1. Generate/record integrated loads and point pressure measurements by creating and running a CFD model on DesignSafe.

    2. Run GeoClaw, a widely used shallow-water solver vetted for tsunamis / storm surges, via the graphical user interface.

    3. For advanced users, full authority is provided to input hydrodynamic files from tools of their choice.

    4. Define and adjust prebuilt, digital twin wave-makers (piston based, vacuum-chamber release).

    5. Simulate coastal wave events using the Celeris wave-solver (Boussinesq, non-linear shallow water).

    6. Access BRAILS building inventories and NOAA bathymetry-topographies through the Celeris module coupling.

    7. Employ local high-performance computation (GPU & CPU) using Taichi Lang (examples provided).

  2. Structural Model: Defines the structural modeling approach and returns the scripts required to perform the response simulation. One or more models can be assigned to a workflow. Using more than one model allows for benchmarking and epistemic uncertainty analysis. The following options are available:

    1. Provide your own OpenSees model in Tcl or Python format.

    2. Provide a Python script that prepares a structural model and performs the response simulation.

    3. Automatically generate an idealized shear column model in OpenSees from basic building information.

  3. Response Simulation: Defines the analysis options that will be used to perform the numerical simulation, e.g., time integration strategy, convergence criteria, and damping options. The user-specified modeling tool is used to perform the simulation and collect the requested response quantities.

5.1. UQ (Uncertainty Quantification and Optimization Options)

  1. Uncertainty Quantification: Samples the prescribed random input variables and obtains realizations of the outputs by executing the workflow with each input realization from the generated sample. The underlying UQ engines let you leverage the following techniques in your research:

    1. Forward propagation Dakota SimCenterUQ: Define a set of random input parameters and perform simulations to obtain a corresponding sample of output parameters and their statistics.

    2. Sensitivity analysis Dakota SimCenterUQ: Measure the influence of the uncertainty in each input on the uncertainty of outputs.

    3. Reliability analysis Dakota SimCenterUQ: Algorithms to estimate the probability of exceeding a failure surface.

5.3. EVT (Event Selection)

  1. Style

    1. General Event

      1. Broad functionality for designing custom events with custom bathymetry, structures, initial conditions, etc.

    2. Digital Twins

      1. Prevalidated digital wave-flumes replicating experimental facilities

      2. Available digital wave-flumes

        1. Oregon State University Large Wave Flume (OSU LWF)

        2. Oregon State University Directional Wave Basin (OSU DWB)

        3. University of Washington’s Wind-and-Sea Interaction Facility (UW WASIRF)

        4. Waseda University’s Tsunami Wave Basin (WU TWB)

        5. United States Geological Survey Debris-Flow Flume (USGS DFF)

      3. Available wave-maker twins

        1. 1D Piston

        2. Vacuum Chamber Reservoir

        3. Dam-break

  2. Numerical Methods

    1. Material Point Method (ClaymoreUW MPM)

      1. Unified debris-fluid-structure-soil interaction simulations using Material Point Method (MPM)

      2. Accepts custom event probe types and locations

      3. Multi-GPU accelerated

      4. Available for running on TACC HPC

    2. Celeris

      1. Boussinesq wave solver

      2. Nonlinear shallow-water solver

      3. Accepts custom bathymetries and event probe locations

      4. Automatic BRAILS inventory with NOAA bathymetries

      5. Taichi Lang accelerated (GPU & CPU).

      6. Available for running on local machine

    3. FOAMySees (Returning Soon) 1

      1. Computational Fluid Dynamics using OpenFOAM

      2. Computational Structural Dynamics using OpenSees

      3. Two-way coupled using Precice library

      4. Available for running on TACC HPC

    4. OpenFOAM (Returning Soon) 2

      1. Computational Fluid Dynamics

      2. Partially deprecated functionality for allowing inlets for GeoClaw / generic shallow-water equation solutions in OpenFOAM 2

      3. Available for running on TACC HPC

    5. GeoClaw (Returning Soon) 2

      1. Shallow-water solver for tsunamis and storm surges

      2. Available for running on DesignSafe

      3. Available for running on local machine

      4. Available for running on TACC HPC

Note

1 FOAMySees functionality from HydroUQ v2.0 is deprecated in the current version due to remote supercomputer migration from Frontera to Stampede3. It is to be fully reintroduced in the near future if funding returns to this project. 2 OpenFOAM-GeoClaw functionality from HydroUQ v1.0 is deprecated in the current version due to remote supercomputer migration from Frontera to Stampede3. It is to be fully reintroduced in the near future if funding returns to this project.

5.6. EDP (Outputs from Computational Models)

  1. Available sets of EDPs:

    1. Standard Earthquake EDPs

      1. Peak Inter-story Drift (PID)

      2. Peak Floor Acceleration (PFA)

      3. Peak Roof Displacement (PRD)

    2. Standard Hydrodynamic EDPs

      1. Peak floor displacement (PFD)

      2. Peak floor acceleration (PFA)

      3. Peak floor force (PFF)

      4. Peak floor pressure (PFP)

      5. Peak wave height (PWH)

      6. Average wave velocity (AWV)

      7. Total wave momentum-flux (TWM)

    3. User Defined EDPs

      1. Define EDPs in the additional input files

      2. Populate response parameter names in the GUI

      3. Define a post-processing script to create the results.out file of appropriate format (single line where each value corresponds to a response parameter) using only the FEM simulation output.

      4. Use the output of the FEM simulation to calculate the EDPs

  2. Format of EDPs:

    1. Scalar quantities of interest

    2. Vector quantities of interest
